# notion-tui M11 — Automated Release Pipeline: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One merged PR becomes a semver-bumped, changelogged, crates.io-published, binary-distributed GitHub Release with zero manual steps.

**Architecture:** The git root is the monorepo `/Users/rehatbir/Developer/fables`; the Cargo workspace lives in the `notion-tui/` subdirectory, so every tool is configured for that split: release-plz runs with `manifest_path: notion-tui/Cargo.toml` and a package-prefixed tag (`notion-tui-vX.Y.Z`), and dist is pointed at the subdirectory via a repo-root `dist-workspace.toml` with `members = ["cargo:notion-tui/"]`. The trigger chain is: push to `main` → release-plz opens/updates a release PR (bumps + changelog) → merging that PR makes release-plz push the `notion-tui-vX.Y.Z` tag (publish disabled — tag only) → the tag triggers dist's generated `release.yml`, which runs the M6 three-OS gate as a custom plan job, builds five binary target sets, and only then runs the publish jobs (crates.io in dependency order, Homebrew tap) before creating the GitHub Release in the announce phase.

**Tech Stack:** release-plz (`release-plz/action@v0.5`), dist (cargo-dist) v0.32.0, `amannn/action-semantic-pull-request@v6`, GitHub Actions (`actions/checkout@v4`, `dtolnay/rust-toolchain@stable`, `Swatinem/rust-cache@v2`).

## Global Constraints

- **Unified workspace version:** all four crates inherit `[workspace.package].version` from `notion-tui/Cargo.toml`; one release bumps everything in lockstep (currently `0.1.1`).
- **Publish order:** `notion-tui-api`, `notion-tui-store` (leaves) → `notion-tui-sync` → `notion-tui` (bin); `cargo publish` waits for index visibility between crates.
- **Three-OS gate before anything publishes:** the release workflow runs the full M6 gate (`cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --check` on ubuntu/macos/windows) as a dist plan-phase job; builds and publishes depend on it.
- **Tag format is `notion-tui-vX.Y.Z` everywhere:** produced by release-plz (`git_tag_name = "notion-tui-v{{ version }}"`), consumed by dist as a "singular announcement" tag (`<package>-v<version>` — dist book, workspaces/workspace-guide). Never a bare `vX.Y.Z` — the monorepo hosts other projects.
- **Never half-publish:** crates.io publish is a dist custom publish job (runs only after every binary built and hosted), and the GitHub Release is created in the announce phase (`github-release = "announce"`) — after crates.io and Homebrew succeed. A failure anywhere leaves no user-visible release.
- **Monorepo paths:** all workflow files live at `/Users/rehatbir/Developer/fables/.github/workflows/`; `dist-workspace.toml` lives at the monorepo root; `release-plz.toml` lives in `notion-tui/`; all `cargo`/`release-plz` commands run from `/Users/rehatbir/Developer/fables/notion-tui`; `dist` commands run from the monorepo root.
- **`.github/workflows/release.yml` is generated by `dist generate` — never hand-edit it.** All customization goes through `dist-workspace.toml`; regenerate after every config change.
- **The working tree contains uncommitted M6/M7 work.** Workers do NOT run `git commit`/`git push`/`git tag`. Each task ends with a *commit checkpoint* listing exact, file-scoped commands for the session owner (never `git add -A` — it would sweep in unrelated work). Verification steps that need commits/tags happen in a throwaway clone or are marked "session owner".

- [ ] **Step 2: Write the release-plz workflow**

Create `/Users/rehatbir/Developer/fables/.github/workflows/notion-tui-release-plz.yml`:

```yaml
name: notion-tui release-plz

on:
  push:
    branches: [main]
    paths:
      - "notion-tui/**"
      - ".github/workflows/notion-tui-release-plz.yml"

jobs:
  # Open/update the release PR (version bumps + changelog) after pushes to main.
  release-plz-pr:
    name: Release PR
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
    concurrency:
      group: release-plz-${{ github.ref }}
      cancel-in-progress: false
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 0
          persist-credentials: false
      - name: Install Rust toolchain
        uses: dtolnay/rust-toolchain@stable
      - name: Run release-plz release-pr
        uses: release-plz/action@v0.5
        with:
          command: release-pr
          manifest_path: notion-tui/Cargo.toml
          config: notion-tui/release-plz.toml
        env:
          GITHUB_TOKEN: ${{ secrets.RELEASE_PLZ_TOKEN }}
          CARGO_REGISTRY_TOKEN: ${{ secrets.CARGO_REGISTRY_TOKEN }}

  # When the push IS a merged release PR, push the notion-tui-vX.Y.Z tag.
  # publish=false + git_release_enable=false in release-plz.toml mean this job
  # ONLY tags; the tag triggers .github/workflows/release.yml (dist), which
  # gates, builds, publishes crates.io + Homebrew, and creates the GitHub
  # Release. RELEASE_PLZ_TOKEN must be a PAT: tags pushed with the default
  # GITHUB_TOKEN do not trigger other workflows (release-plz docs, github/token).
  release-plz-tag:
    name: Tag release
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: read
    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          fetch-depth: 0
          persist-credentials: false
      - name: Install Rust toolchain
        uses: dtolnay/rust-toolchain@stable
      - name: Run release-plz release
        uses: release-plz/action@v0.5
        with:
          command: release
          manifest_path: notion-tui/Cargo.toml
          config: notion-tui/release-plz.toml
        env:
          GITHUB_TOKEN: ${{ secrets.RELEASE_PLZ_TOKEN }}
          CARGO_REGISTRY_TOKEN: ${{ secrets.CARGO_REGISTRY_TOKEN }}
```

(Two-job shape, `fetch-depth: 0`, `persist-credentials: false`, and permissions follow the release-plz GitHub quickstart; `manifest_path` and `config` inputs are documented at release-plz.dev/docs/github/input and are relative to the checkout root — i.e. the monorepo root.)

- [ ] **Step 1: Write the reusable gate workflow**

Create `/Users/rehatbir/Developer/fables/.github/workflows/notion-tui-release-gate.yml`. It duplicates the M6 CI matrix on purpose: `notion-tui-ci.yml` stays untouched as the PR/push gate, and this one is shaped as a dist custom job (dist requires custom jobs to be reusable workflows taking a required string input named `plan` — dist book, ci/customizing):

```yaml
name: notion-tui release gate

# Reusable workflow invoked by dist's generated release.yml as a custom
# plan-phase job (dist-workspace.toml: plan-jobs = ["./notion-tui-release-gate"]).
# Runs the full M6 CI gate on all three OSes; every build/publish phase of the
# release depends on this job, so a red gate blocks the release entirely.
on:
  workflow_call:
    inputs:
      plan:
        required: true
        type: string

defaults:
  run:
    working-directory: notion-tui

jobs:
  gate:
    name: Release gate
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
    runs-on: ${{ matrix.os }}
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
        with:
          components: rustfmt, clippy
      - uses: Swatinem/rust-cache@v2
        with:
          workspaces: notion-tui
      - name: Test
        run: cargo test --workspace
      - name: Clippy
        run: cargo clippy --workspace --all-targets -- -D warnings
      - name: Format
        run: cargo fmt --check
```

```yaml
        shell: bash
        run: |
          set -euo pipefail
          version="$(cargo metadata --no-deps --format-version 1 \
            | jq -r '.packages[] | select(.name == "notion-tui") | .version')"
          if [[ "$version" == *-* ]]; then
            # Belt-and-suspenders: dist already skips publish jobs on
            # prerelease tags (publish-prereleases defaults to false).
            echo "prerelease version $version — skipping crates.io publish"
            exit 0
          fi
          # Dependency order: api and store are leaves; sync depends on both;
          # notion-tui (bin) depends on all three. `cargo publish` blocks until
          # each crate is visible in the index, so the next publish resolves it.
          # The already-published check makes workflow re-runs idempotent.
          for pkg in notion-tui-api notion-tui-store notion-tui-sync notion-tui; do
            if curl -fsS "https://crates.io/api/v1/crates/${pkg}/${version}" >/dev/null 2>&1; then
              echo "${pkg} ${version} already on crates.io — skipping"
              continue
            fi
            cargo publish -p "$pkg" --locked
          done
```
